# Студенческие работы по языку C

Репозиторий преподавателя (upstream): <https://github.com/hsgapworks/students>

Репозиторий публичный. Каждый студент работает в своём fork'е и отправляет pull
request в upstream. Принятые работы лежат в ветке `main` upstream-репозитория.
Задание считается сданным, когда pull request одобрен и слит преподавателем.

## Содержание

Пошаговые инструкции уже приведены в файле ниже — дублировать их не нужно:

- клонирование своего fork'а — «Вариант А: клонирование через VS Code»,
  «Вариант Б: клонирование через командную строку»,
  «Вариант В: GitHub Desktop (необязательно)»;
- поиск папки на Windows — «Где найти папку репозитория на Windows»;
- добавление своих файлов — «Как добавить свои файлы»;
- создание отдельной ветки — «Как сдать задание: pull request», команда
  `git checkout -b <имя-ветки>` с пояснениями; для GitHub Desktop —
  «Вариант В: GitHub Desktop (необязательно)», шаг 1 (`New Branch`);
- сдача задания — «Как сдать задание: pull request»,
  «Сдача pull request'а через GitHub CLI (`gh`)»;
- обновление fork'а — «Обновление fork'а после слияния PR»;
- если что-то не работает — «Частые ошибки».

## Структура репозитория

```
students/
├── jane.doe/            <- пример: папка студента
│   └── 1/
│       ├── main.c
│       └── examplefile.c
├── john.doe/            <- пример: второй студент
│   └── 2/
│       └── main.c
└── README.md
```

- Имя папки студента — **реальное Имя и Фамилия** (например, `Иванов Иван`).
  Это НЕ GitHub-логин. Логин может отличаться от имени папки.
- Внутри папки — подпапки по номерам заданий: `1`, `2`, ... `6`.
- Исходники — файлы `.c` и `.h`. Исполняемые файлы, `.o`, `.exe` и подобные
  игнорируются через `.gitignore` и в репозиторий не попадают.

## Доступ: сделать до начала работы

1. Завести аккаунт на GitHub (если ещё нет).
2. Сделать fork репозитория: открыть <https://github.com/hsgapworks/students>
   и нажать `Fork`. Появится репозиторий `https://github.com/<ВашЛогин>/students`.
3. Клонировать **свой fork**, а не репозиторий преподавателя. Готовые пошаговые
   инструкции уже есть ниже: «Вариант А: клонирование через VS Code»,
   «Вариант Б: клонирование через командную строку» либо
   «Вариант В: GitHub Desktop (необязательно)».

Все последующие push идут в свой fork (`origin`). Pull request отправляется
в `hsgapworks/students` (`upstream`).

На выполнение заданий 1-6 отводится 12 недель из 16. Первые две недели
семестра — освоение git, GitHub и процедуры сдачи на практикуме. Программы
разрабатываются на языке C. В заданиях 5 и 6 требуются функции.

## Постановки заданий

### Задание 1

Фирма «Умелые ручки» выпускает двухдверные одежные шкафы.

Состав шкафа:

- накладная задняя стенка из ДВП высотой `h` от 180 до 220 см, шириной `w` от 80 до 120 см и толщиной 5 мм;
- две боковины из ДСП высотой `h`, глубиной `d` от 50 до 90 см и толщиной 15 мм;
- накладные верхняя и нижняя крышки из ДСП шириной `w`, глубиной `d` и толщиной 15 мм;
- две накладные двери из дерева высотой `h`, общей шириной `w` и толщиной 1 см;
- внутренние полки в шкафу через каждый 40 см из ДСП.

Считая, что известны плотности ДСП, ДВП и дерева, найти массу шкафа.

### Задание 1'

Дана шахматная доска. Для двух различных клеток `К1`, `К2` доски и выбранной пользователем фигуры (король, ферзь, ладья, слон, конь) определить:

- Может ли фигура за один ход перейти из `К1` в `К2`?
- Если нет, могут ли это сделать какие-то из остальных фигур? Если могут, вывести их список.

### Задание 2

Разработать программу «Угадай число». В программе должно быть предусмотрено два режима.

**Режим 1.** Программа «загадывает» случайное число из диапазона от 1 до 1000. Пользователь должен вводить отгадки, на которые программа сообщает: «загаданное число больше», «загаданное число меньше», «угадали». Работа завершается, когда пользователь угадает число. Также программа должна подсчитывать число попыток и выводить его в конце работы.

**Режим 2.** Пользователь загадывает число из диапазона от 1 до 1000 и вводит его. Программа пытается «угадать» число, выводя на экран отгадки, на которые пользователь вводит `>`, `<` или `=`. Работа завершается, когда программа угадает число. Также программа должна подсчитывать число попыток и выводить его в конце работы.

### Задание 2'

Разработать программу, которая считает количество слов и количество чисел во входном потоке символов. Словом считать последовательность символов английского или русского алфавитов, числом — последовательность цифр. Слова и числа во входном потоке отделяются друг от друга пробелами (одним или несколькими) или символами табуляции. Поток завершается символом перевода строки.

### Задание 3

Разработать программу, реализующую игру «Быки и коровы».

Требования (правила):

- Играют два игрока (человек и компьютер).
- Игрок выбирает длину загадываемого числа — `n` (от 2 до 5).
- Компьютер «задумывает» `n`-значное число с неповторяющимися цифрами.
- Игрок делает попытку отгадать число — вводит `n`-значное число с неповторяющимися цифрами.
- Компьютер сообщает, сколько цифр угадано без совпадения с их позициями в загаданном числе (количество коров) и сколько угадано вплоть до позиции в загаданном числе (количество быков).
- Игрок делает попытки, пока не отгадает всю последовательность.

Пример:

- Пусть `n = 4`.
- Пусть задумано число «3219».
- Игрок ввел число «2310».
- Результат: две «коровы» (цифры «2» и «3» угаданы на неверных позициях) и один «бык» (цифра «1» угадана вплоть до позиции).

### Задание 4

Разработать программу «Электронная касса». Программа должна имитировать работу кассового аппарата по сканированию товаров и формированию чека за покупку.

Каждый товар идентифицируется штрих-кодом. Штрих-код хранится в виде массива из четырех символов. Каждый символ принимает значение от `0` до `9`. Один и тот же товар может сканироваться несколько раз, но в чек информация о каждом товаре входит в виде «наименование — стоимость за единицу (для упрощения в рублях без копеек) — количество — общая стоимость за товар». Чек состоит не менее чем из одной записи указанного вида. Чек дополнительно включает общую стоимость товаров в покупке, суммарную скидку и итоговую сумму к оплате (все в рублях).

Каждый товар описывается штрих-кодом, наименованием, стоимостью за единицу товара, скидкой в процентах от стоимости. Скидки устанавливаются на каждый товар независимо (в диапазоне от 1 до 50%).

Программа должна предоставлять следующие операции:

1. «сканировать» очередной товар;
2. вывести описание отсканированного товара;
3. добавить данные о товаре в чек;
4. сформировать чек за покупку;
5. рассчитать итоговую сумму к оплате.

### Задание 5

Разработать прототип файлового менеджера с функцией показа файлов в заданном каталоге, упорядоченных по возрастанию/убыванию размера.

Входные данные:

- путь до директории, в которой необходимо отсортировать содержимое;
- метод сортировки.

Выходные данные:

- отсортированный список имен файлов с указанием размера;
- время сортировки.

Программа должна предоставлять пользователю возможность сменить метод сортировки и повторно формировать выходные данные.

Программа должна реализовывать диалог с пользователем посредством интерфейса, который включает:

- возможность ввода пути до заданного каталога;
- возможность выбора метода сортировки;
- возможность просмотра отсортированного списка файлов с указанием размера.

Полный список методов сортировки задается отдельно. Методы, которые должен будет реализовать каждый студент, также определяются отдельно.

### Задание 6

Разработать программу, позволяющую выполнять расчет значений для некоторого набора функций в заданной точке с заданной погрешностью за счет разложения этих функций в ряд Тейлора.

Программа должна работать в двух режимах:

1. однократный расчет функции в заданной точке;
2. серийный эксперимент.

При работе в режиме 1 пользователь должен иметь возможность:

- выбрать функцию;
- задать точку `x`, в которой необходимо вычислить значение;
- задать точность вычисления (от 0.000001 и больше);
- задать число элементов ряда для выполнения расчета (`N` от 1 до 1000).

Расчет оценки значения выбранной функции выполняется либо до достижения заданной точности, либо до исчерпания введенного числа слагаемых. По результатам расчета программа должна вывести:

- эталонное значение (полученное с использованием встроенных математических функций языка C);
- вычисленную оценку значения функции;
- разницу между оценкой и эталонным значением;
- количество слагаемых, которое было вычислено.

При работе в режиме 2 пользователь должен иметь возможность:

- выбрать функцию;
- задать точку `x`, в которой необходимо вычислить значение;
- задать число экспериментов (`NMax` от 1 до 25).

По результатам расчета программа должна вывести:

- эталонное значение (полученное с использованием встроенных математических функций языка C);
- таблицу из `NMax` строк со столбцами: кол-во слагаемых (от 1 до `NMax`), вычисленная оценка значения функции, разница между оценкой и эталонным значением.

Технические требования:

- использован механизм функций языка C;
- использован тип указатель на функцию;
- желательно использовать модули;
- каждый студент реализует расчет функций `sin(x)`, `cos(x)`, `exp(x)` и одной уникальной функции из списка ниже. Номер требуемой функции совпадает с номером в списке группы.

Уникальные функции:

- тангенс `tg(x)`;
- гиперболический косинус `ch(x)`;
- арксинус `arcsin(x)`;
- косеканс `csc(x)`;
- гиперболический котангенс `cth(x)`;
- логарифм `ln(x)`;
- логарифм от `1+x` — `ln(1+x)`;
- секанс `sec(x)`;
- квадратный корень из `1+x` — `(1+x)^1/2`;
- арктангенс `arctg(x)`;
- котангенс `ctg(x)`;
- арккотангенс `arcctg(x)`;
- гиперболический тангенс `th(x)`;
- гиперболический синус `sh(x)`;
- обратный гиперболический синус `arsh(x)`;
- арккосинус `arccos(x)`.

## Подготовка рабочего места (Windows)

Обязательно:

1. **Git.** Откройте <https://git-scm.com/download/win>, скачайте установщик
   для Windows, запустите его. Нажимайте `Next`, настройки по умолчанию
   подходят. Вместе с Git установится `Git Bash`.
2. **VS Code.** Скачайте с <https://code.visualstudio.com/>, запустите
   установщик, настройки по умолчанию подходят. Если используете другую среду
   разработки — установите её вместо VS Code.

Необязательно:

3. **GitHub CLI (`gh`)** — только для сдачи pull request из терминала.
   Установка через командную строку (`Win + R` -> `cmd`):

   ```
   winget install GitHub.cli
   ```

   Либо скачайте установщик с <https://cli.github.com/>.
4. **GitHub Desktop** — только для тех, кто не хочет работать с git вручную.
   Скачайте с <https://desktop.github.com/download/> и запустите установщик.
   Отдельная установка Git из пункта 1 всё равно нужна: VS Code и терминал
   используют её, встроенный Git Desktop их не заменяет.

Проверка установки. Откройте командную строку (`Win + R` -> `cmd`) и выполните:

```
git --version
gh --version
```

Должны появиться версии, например `git version 2.45.0` и `gh version 2.102.0`.
Команда `gh --version` нужна только если установлен GitHub CLI.

Первый запуск GitHub CLI — авторизация (делается один раз):

```
gh auth login
```

Выберите `GitHub.com` -> `HTTPS` -> `Login with a web browser`, скопируйте
одноразовый код и вставьте его в браузере.

## Вариант А: клонирование через VS Code

1. Запустите VS Code.
2. Нажмите `Ctrl + Shift + P` (откроется строка команд).
3. Введите `Git: Clone` и выберите эту команду.
4. Вставьте URL своего fork (подставьте свой GitHub-логин):

   ```
   https://github.com/<ВашЛогин>/students.git
   ```

5. Выберите папку, куда положить копию. Запомните её. Рекомендуется, например,
   `C:\Users\<ВашЛогин>\students`.
6. После клонирования VS Code спросит «Open Repository?» / «Открыть репозиторий?»
   — согласитесь. Если не спросил: `File` -> `Open Folder` и выберите папку
   `students`.
7. Слева в панели `Explorer` (`Ctrl + Shift + E`) появится дерево файлов
   репозитория. Это и есть ваша рабочая папка.
8. Добавьте репозиторий преподавателя как `upstream`. Откройте встроенный
   терминал (`Ctrl + backtick`) и выполните:

   ```
   git remote add upstream https://github.com/hsgapworks/students.git
   git remote -v
   ```

   В выводе должны быть `origin` (ваш fork) и `upstream` (репозиторий преподавателя).

## Вариант Б: клонирование через командную строку

Для тех, кто работает в другой среде разработки. Откройте `cmd` или `PowerShell`
и выполните:

```
cd C:\Users\<ВашЛогин>
git clone https://github.com/<ВашЛогин>/students.git
cd students
git remote add upstream https://github.com/hsgapworks/students.git
git remote -v
```

Проверка:

```
git status
```

Должно быть `On branch main` и `Your branch is up to date with 'origin/main'.`
`origin` — ваш fork, `upstream` — репозиторий преподавателя.

Ту же папку можно открыть в любой среде: в VS Code `File` -> `Open Folder` ->
выберите `C:\Users\<ВашЛогин>\students`.

## Вариант В: GitHub Desktop (необязательно)

GitHub Desktop удобен для коммитов и pull request'ов, но одного его недостаточно:
нет редактора кода, нет компиляции, через интерфейс нельзя добавить `upstream`
и синхронизировать fork. VS Code (или другой редактор) и терминал нужны в любом случае.

Настройка один раз:

1. Запустите GitHub Desktop. Откройте `File` -> `Options` (в macOS `Preferences`)
   -> `Accounts`, нажмите `Sign in`, выберите `GitHub.com` и авторизуйтесь в браузере.
2. Сделайте fork репозитория на сайте: <https://github.com/hsgapworks/students>
   -> кнопка `Fork`.
3. В GitHub Desktop выберите `File` -> `Clone repository`, вкладку `GitHub.com`,
   выберите `<ВашЛогин>/students`, укажите локальную папку и нажмите `Clone`.
4. Добавьте `upstream` через терминал: `Repository` -> `Open in Terminal` и выполните:

   ```
   git remote add upstream https://github.com/hsgapworks/students.git
   git remote -v
   ```

   GitHub Desktop не показывает второй remote в своём интерфейсе, поэтому
   синхронизация с репозиторием преподавателя делается только в терминале.

Работа с заданием:

1. `Current branch` -> `New Branch`. Имя ветки латиницей, без пробелов,
   например `ivanov-task1`.
2. Добавьте свои `.c`-файлы в папку репозитория через Проводник или VS Code.
   GitHub Desktop покажет их в списке изменений слева.
3. Внизу в поле `Summary` введите сообщение, например `Задание 1`, и нажмите
   `Commit to ivanov-task1`.
4. Нажмите `Push origin` — ветка уйдёт в ваш fork.
5. Нажмите `Create Pull Request`. Откроется браузер. Проверьте
   `base repository` = `hsgapworks/students`, `base` = `main`,
   `head repository` = `<ВашЛогин>/students`, `compare` = ваша ветка.
   Нажмите `Create pull request`.

Синхронизация перед следующим заданием. Откройте `Repository` ->
`Open in Terminal` и выполните:

```
git checkout main
git fetch upstream
git merge upstream/main
git push origin main
```

После этого в GitHub Desktop переключитесь на `main` через `Current branch`
и создайте новую ветку под следующее задание.

Компиляцию GitHub Desktop не запускает. Используйте `Repository` ->
`Open in Terminal` и команды `gcc` из README нужного задания либо встроенный
терминал VS Code.

## Где найти папку репозитория на Windows

Если потеряли папку:

- В VS Code: правый клик по папке `students` в `Explorer` ->
  `Reveal in File Explorer` («Показать в Проводнике»).
- В Проводнике: вставьте путь в адресную строку, например
  `C:\Users\<ВашЛогин>\students` и нажмите Enter.
- В терминале: команда `cd` показывает текущую папку, `dir` — её содержимое.

Проверка, что вы в нужном месте: в папке должны быть `README.md` и `.gitignore`.

## Как добавить свои файлы

1. В VS Code в панели `Explorer` правый клик по `students` ->
   `New Folder`. Создайте папку со своим именем и фамилией, например `Иванов Иван`.
   Если такая папка уже есть — используйте её.
2. Внутри создайте папку с номером задания, например `1`.
3. Добавьте файлы одним из способов:
   - правый клик по папке задания -> `New File` -> введите имя, например `main.c`;
   - или скопируйте готовый `.c`-файл из Проводника и вставьте в папку задания
     в `Explorer` (`Ctrl + V`).
4. Откройте файл двойным кликом и проверьте, что код виден в редакторе.

Важно: не переименовывайте папку каждого задания в логин GitHub. Папка — это
имя/фамилия, а не логин.

Проверить, что файлы попали под контроль версий, можно в терминале:

```
git status
```

Новые файлы появятся в разделе `Untracked files`.

## Как сдать задание: pull request

Сдаётся каждое задание отдельным pull request'ом. Работать напрямую в `main` не надо.
Push делается в свой fork (`origin`), pull request — в upstream.

Откройте встроенный терминал VS Code: `Ctrl + backtick` (
клавиша `ё` / `` ` ``). Либо используйте обычный `cmd`, перейдя в папку
клонированного fork'а командой `cd`.

Последовательность команд (пример для задания 1):

```
git checkout main
git fetch upstream
git merge upstream/main
git checkout -b ivanov-task1
git add "Иванов Иван/1/"
git commit -m "Задание 1"
git push -u origin ivanov-task1
```

Первые три команды синхронизируют fork с upstream перед новой работой.
Если `git merge` говорит `Already up to date` — это нормально.

Пояснения:

- `git checkout -b ivanov-task1` — создаёт новую ветку и переключается на неё.
  Имя ветки пишите латиницей, без пробелов, например `ivanov-task1`.
- `git add "Иванов Иван/1/"` — добавляет в коммит вашу папку с заданием.
  Кавычки нужны из-за пробела в имени папки.
- `git commit -m "Задание 1"` — создаёт коммит с сообщением.
- `git push -u origin ivanov-task1` — отправляет ветку в ваш fork на GitHub.
  `origin` — fork, `upstream` — репозиторий преподавателя.

Дальше — через сайт GitHub:

1. Откройте страницу своего fork: `https://github.com/<ВашЛогин>/students`.
2. Перейдите во вкладку `Pull requests` -> `New pull request`.
3. `base repository` выберите `hsgapworks/students`, `base` — `main`.
4. `head repository` выберите `<ВашЛогин>/students`, `compare` — свою ветку
   (например, `ivanov-task1`).
5. Нажмите `Create pull request`, заполните заголовок (например, `Иванов Иван — задание 1`)
   и при необходимости опишите задание.
6. Нажмите `Create pull request` ещё раз.

Если `New pull request` не показывает upstream: откройте страницу upstream
`https://github.com/hsgapworks/students` -> `Pull requests` ->
`New pull request` -> `Compare across forks` и выберите свой fork и ветку.

После проверки преподаватель одобряет и сливает PR. Задание засчитано.

## Сдача pull request'а через GitHub CLI (`gh`)

Можно не заходить на сайт. Если `gh` ещё не авторизован, выполните
`gh auth login` — пошаговая инструкция в разделе «Подготовка рабочего места (Windows)».

Затем для своей ветки (команда выполняется из папки fork'а):

```
gh pr create --repo hsgapworks/students --base main --head <ВашЛогин>:ivanov-task1 --title "Иванов Иван — задание 1" --body "Задание 1"
```

`<ВашЛогин>` замените на свой GitHub-логин. Флаг `--repo hsgapworks/students`
указывает, что PR создаётся в upstream, а не в вашем fork'е.

Проверить статус:

```
gh pr status
```

## Обновление fork'а после слияния PR

После того как преподаватель слил PR, ваш fork отстаёт от upstream. Перед
следующим заданием синхронизируйтесь:

```
git checkout main
git fetch upstream
git merge upstream/main
git push origin main
```

## Частые ошибки

- `Permission denied` при `git push` — вы пытаетесь запушить в upstream. Push
  делается только в `origin` (ваш fork). Проверьте: `git remote -v`.
- `git push` говорит «no upstream branch» — используйте `git push -u origin <ветка>`.
- Файл не отображается в `git status` — проверьте, что он лежит в папке клонированного
  fork'а (`git status` показывает `Untracked files`), и что он не `.exe`/`.o`
  (такие файлы игнорируются).
- В имени папки пробел — при работе с git из командной строки заключайте путь в кавычки.
- Pull request не создаётся — проверьте, что ветка запушена в fork
  (`git push -u origin <ветка>`), что `base repository` = `hsgapworks/students`,
  а `head repository` — ваш fork.
- В `compare` видна только ваша ветка, но не upstream — проверьте, что добавлен
  remote `upstream`: `git remote add upstream https://github.com/hsgapworks/students.git`.

## Краткие правила

- Репозиторий публичный: fork обязателен, приглашение не нужно.
- Одна папка на студента: реальные Имя и Фамилия.
- Одна подпапка на задание: `1` ... `6`.
- Push — в свой fork (`origin`), pull request — в upstream (`hsgapworks/students`).
- Один pull request на задание, `base` = `main`.
